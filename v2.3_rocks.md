# Gondola v2.3: Why It Works

## Executive Summary

v2.3 is minimal, focused, and effective. It does exactly what's needed and nothing more. The result: a simple 5-line fix takes 5,000 tokens and completes successfully.

---

## 1. THE PROMPT: ~500 TOKENS OF CLARITY

### The Base System Prompt

**File:** `cortex/prompts/system.py` (lines 75-95)

```python
BASE_SYSTEM_PROMPT = """You are an autonomous AI coding agent.

## MANDATES:
1. **COMMUNICATE**: Always provide a natural language response in the chat window explaining what you did or providing your final answer BEFORE calling `done()`. Do not just call the tool silently.
2. **COMPLETE YOUR TASK**: Call `done()` with your final summary only after you have provided your textual response to the user.
3. **EFFICIENCY**: Read files ONCE. No duplicate reads.
4. **VERIFY**: Check tool results for `"success": false`. Fix errors immediately.
5. **STOP**: If you have the answer, explain it to the user and then call `done()`. Don't keep exploring.

## TOOLS:
- `list_files(path, pattern)`
- `read_file(filename)`
- `search_file_content(pattern, path)`
- `get_skeleton(filename)`: Get file structure
- `symbol_jump(symbol_name)`: Jump to definition
- `inspect_type(filename, symbol)`: Signature/type info
- `write_file(filename, content)`
- `edit_file(filename, old_text, new_text)`
- `run_command(command)`
- `done(summary)`: **REQUIRED** to finish

## EDIT PROTOCOL:
High-risk edits are BLOCKED. If blocked, verify (e.g., `read_file`) then retry with `verify_risk=true`.
"""
```

**Why It Works:**
- **Clear identity**: "You are an autonomous AI coding agent."
- **Numbered mandates**: 5 rules, not 50
- **Tool reference**: Quick lookup, not verbose descriptions
- **Hard stop**: `done()` is **REQUIRED**, not optional

**Token Count:** ~500 tokens. Compare to v3's 8,000-15,000 tokens.

## 4. BUILD_SYSTEM_PROMPT: STRAIGHTFORWARD BUILDER

### The Function

**File:** `cortex/prompts/system.py` (lines 258-310)

```python
def build_system_prompt(
    model_id: str = None,
    project_context: str = None,
    turn_count: int = 0,
    max_turns: int = 20,
    files_already_read: list = None,
    resurrection_context: str = None,
    planning_mode: bool = False,
    memory_context: str = None
) -> str:
    parts = [BASE_SYSTEM_PROMPT]

    # Inject personality if set
    personality = load_personality()
    if personality:
        parts.append(f"\n{personality}\n")

    # Add planning mode if enabled
    if planning_mode:
        parts.append(PLANNING_MODE_PROMPT)

    # Add memory context if available
    if memory_context:
        parts.append(f"\n## MEMORY:\n\n{memory_context}")

    # Add resurrection context if available
    if resurrection_context:
        parts.append(f"\n## RESURRECTION POINT:\n\n{resurrection_context}...")

    # Add stopping criteria
    parts.append(STOPPING_CRITERIA)

    # Add model-specific guidance (conditional)
    if model_id and model_id in MODEL_SPECIFIC_GUIDANCE:
        parts.append(MODEL_SPECIFIC_GUIDANCE[model_id])

    # Add project context if available
    if project_context:
        parts.append(f"\n## PROJECT OVERVIEW:\n\n{project_context}")

    # Add turn warning only when close to limit
    if turn_count > 0:
        remaining = max_turns - turn_count
        if remaining <= 5:
            parts.append(f"\n## TURN LIMIT WARNING:\n\nYou have {remaining} turns remaining...")
        elif remaining <= 10:
            parts.append(f"\n(Turn {turn_count}/{max_turns})")

    # Add already-read files reminder
    if files_already_read and len(files_already_read) > 0:
        files_list = ', '.join(files_already_read[:10])
        parts.append(f"\n## FILES ALREADY READ:\n\n{files_list}\n\nDo not read these files again.")

    return '\n'.join(parts)
```

**Why It Works:**
- **Linear flow**: No complex branching
- **Conditional injection**: Each block is only added when relevant
- **No self-evaluation prompts**: No "am I taking too long?" overhead
- **No delegation protocol**: Not included because it doesn't exist

**Compare to v3:** v3's `build_system_prompt()` has 7+ blocks injected every turn, including delegation protocol and context bridge.

## 8. THE API: SINGLE EXECUTE_TOOL FUNCTION

### The Function

**File:** `cortex/api.py` (lines 408-696, ~290 lines)

```python
def execute_tool(tool_name: str, args: dict, tools_instance, agent_state) -> dict:
    """Execute a tool by name with the given arguments."""
    
    # Validate tool exists
    if not hasattr(tools_instance, tool_name):
        return {"success": False, "error": f"Unknown tool: {tool_name}"}
    
    # Validate arguments
    validated_args = validate_tool_args(tool_name, args, tools_instance)
    if not validated_args.get("success", True):
        return validated_args
    
    # Execute
    try:
        tool_func = getattr(tools_instance, tool_name)
        result = tool_func(**validated_args)
        return result
    except Exception as e:
        return {"success": False, "error": str(e)}
```

**Why It Works:**
- **Single entry point**: All tools go through this function
- **Validation first**: Checks args before execution
- **Consistent return**: Always returns dict with `success` key
- **Error handling**: Catches exceptions and returns error dict

**Compare to v3:** v3 has `ToolRegistry`, `@tool` decorator, Pydantic `ToolResult` models, and multiple execution paths.

```python
    """Parse XML-style tool calls: <tool>name</tool><args>...</args>"""

def _find_balanced_json(content: str) -> list:
    """Find balanced JSON objects in content."""

    """Parse Python-style calls: tool_name(arg1=value1, ...)"""

def _parse_json_tool_call(content: str) -> list:
    """Parse JSON tool calls: {"tool": "name", "args": {...}}"""

def parse_tool_call(content: str) -> list:
    """Try all parsing methods and return first successful result."""
    parsers = [
        _parse_json_tool_call,
        _parse_xml_tags,
        _parse_python_style_call,
    ]
    for parser in parsers:
        result = parser(content)
        if result:
            return result
    return None
```

**Why It Works:**
- **Multiple formats**: Handles JSON, XML, Python-style
- **Graceful degradation**: Tries each parser in order
- **No schema required**: Works with whatever the model outputs
- **Robust**: Handles malformed input

**Compare to v3:** v3 relies on native function calling only, which fails when models output non-standard formats.

## 11. NO DELEGATION: KEEPING IT SIMPLE

### What's Missing

v2.3 has no:
- `SubAgent` class
- `delegate_task` tool
- Delegation protocol in prompt
- Fork/teammate modes
- Depth limits
- State merging

**Why This Works:**
- **Most tasks don't need delegation**: A 5-line fix is a 5-line fix
- **Delegation adds overhead**: Separate LLM call, separate context
- **Simpler is faster**: One agent, one loop, one result

**When Delegation Would Help:**
- Parallel test execution while coding
- Large-scale refactoring across 10+ files
- Background indexing

**Reality:** Most coding tasks are 1-3 files. Delegation is overhead, not help.

---

## 12. NO CONTEXT BRIDGE: NO SESSION AMNESIA

### What's Missing

v2.3 has no:
- `ContextBridge` class
- Session summary injection
- Trigger engine for summarization
- Token threshold monitoring
- Urgency detection

**Why This Works:**
- **Context is in messages**: The conversation history carries context
- **No duplicate injection**: Don't re-inject what's already in messages
- **Simpler context management**: Just truncate old messages when needed

**Compare to v3:** v3 has a 200-line `TriggerEngine` that monitors tokens, messages, and "urgency" to trigger summarization.

## THE PHILOSOPHY: LESS IS MORE

### v2.3 Follows These Principles:

1. **Do one thing well**: Each function has a single responsibility
2. **Inject lazily**: Context is added only when needed
3. **Enforce strictly**: `done()` is required, not optional
4. **Fail gracefully**: Multiple parsing methods, fallbacks everywhere
5. **Keep it flat**: Plain dicts, not nested objects
6. **No premature abstraction**: Delegation, context bridges, trigger engines don't exist because they weren't needed

### v3 Violates These Principles:

1. **Does too much**: `run_agent_loop` is 350 lines
2. **Injects eagerly**: Context added every turn
3. **Enforces softly**: Warnings are suggestions
4. **Fails on edge cases**: Native-only tool parsing
5. **Nests deeply**: Pydantic models, registries, decorators
6. **Premature abstraction**: Delegation, context bridges, trigger engines built before proving need

## WHAT v2.3 DOESN'T HAVE (AND WHY THAT'S GOOD)

### No Delegation Protocol
- Most tasks don't need it
- Adds latency and token cost
- Solves a problem that doesn't exist for most fixes

### No Context Bridge
- Context is in messages, not injected separately
- Avoids duplicate information
- Simpler mental model

### No Trigger Engine
- No complex token monitoring
- No "urgency detection"
- Just truncate when needed

### No Self-Evaluation Prompts
- Model doesn't waste tokens reasoning about itself
- Focus is on the task, not the process

### No Pydantic Models
- Plain dicts are faster
- No validation overhead
- Easier to debug

### No Event Callbacks
- Simple print statements
- No stream callback complexity
- Works in any environment

## THE LESSON

v2.3 works because it was built incrementally. Features were added when needed, not anticipated. The result is a system that:

1. **Starts small**: ~500 token prompt
2. **Grows on demand**: Context added only when needed
3. **Stops hard**: `done()` is enforced
4. **Fails gracefully**: Multiple fallbacks
5. **Stays flat**: Plain data structures

v3 fails because it anticipated needs that didn't exist. The result is a system that:

1. **Starts big**: ~8,000-15,000 token prompt
2. **Grows always**: Context added every turn
3. **Stops soft**: Warnings are suggestions
4. **Fails on edge cases**: Native-only parsing
5. **Nests deeply**: Pydantic models, registries, decorators

---

## CONCLUSION

v2.3 rocks because it follows the most important principle in software engineering:

> **Do the simplest thing that could possibly work.**

v3 forgot this principle. It built for scale before proving scale was needed. It built for delegation before proving delegation was needed. It built for context management before proving context management was needed.

v2.3 didn't build for the future. It built for the present. And that's why it works.

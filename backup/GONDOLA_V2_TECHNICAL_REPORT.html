Gondola v2.2 Technical Report

A deep-dive analysis of the Necromancer Architecture.

1. System Architecture

Modular Interaction Model

Gondola v2.2 uses a Hybrid Core pattern where the CLI and Web UI are thin wrappers around a heavy Logic Layer.

  • Entry Points: cli.py (CLI) and venice-web-ui/server.py (Flask).
  • Logic Core: venice/api.py (Tool Resolution) and venice/core.py (UI/Model definitions).
  • State Management: venice/agent_state.py (Turn-level tracking) and venice/memory.py (Persistent JSON notes).
  • Toolbox: venice/tools/CombinedTools (A multi-inheritance class merging 5 functional mixins).

2. End-to-End Data Flow

1
Ingestion: User input is received via Flask (POST /api/chat) or CLI input().
2
Resurrection Check: PersistenceManager queries git log _gondola_shadow to retrieve the last RESURRECT: {thought}.
3
Context Assembly: ContextManager.build_messages() combines System Prompt, Project Index Overview (~1000 tokens), and a sliding window of recent conversation history.
4
LLM Dispatch: Payload sent to Venice API via httpx.stream. Native tool calls are accumulated in tool_calls_buffer.

3. Tool Execution Pipeline

venice/api.py -> execute_tool() 
execute_tool(tools: CombinedTools, tool_call: dict):
    # 1. Signature Resolution
    name = tool_call.function.name
    args = json.loads(tool_call.function.arguments)

    # 2. Validation Wrapper (Example: write_file)
    # Detects placeholders like "// code from above" before disk I/O
    if name == "write_file":
        return _validate_and_write_file(tools, args)

    # 3. Dispatch to Mixin
    return tool_map[name]()

6. Surgical Autopsy (Jedi)

venice/undead_manager.py

Manages ephemeral jedi.Script instances for deep type inference.

  • Input: Filename + Symbol + (Tree-sitter Coordinates).
  • Process: 1. Resolve file path. 2. Load source into memory. 3. script.infer(line, column). 4. Extract definition.docstring() and definition.type.
  • Cleanup: No long-running daemon. Memory is reclaimed by Python GC immediately after tool completion.

7. Passive Diagnostics Loop

The Sentry Mechanism

Trigger: Inside file_ops.py, every successful write spawns:

Injection: At turn_start in cli.py/server.py:

if os.path.exists(".gondola_diagnostics.json"):
    diags = json.load(f)

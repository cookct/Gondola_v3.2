Overview

Gondola is an autonomous AI coding agent powered by Venice AI. It provides direct access to your file system and terminal, enabling it to read, write, edit files, run commands, and manage entire projects independently.

Key Features

  • Autonomous Operation - Gondola can explore codebases, plan solutions, and implement changes without constant guidance
  • 30+ Built-in Tools - File operations, code analysis, shell commands, and more
  • Multiple AI Models - Choose from various models based on task complexity and budget
  • Automatic Syntax Verification - Python and JSON files are validated before saving
  • Backup System - Every edit creates an automatic backup for easy recovery
  • Persistent Memory - Remembers context across sessions
  • Vision Support - Analyze images and screenshots

Two Ways to Use Gondola

  1. Web UI - Full-featured graphical interface with real-time terminal output
  2. CLI - Terminal-based interface for quick tasks and scripting

Getting Started

Prerequisites

  • Python 3.8 or higher
  • Venice API key (set as VENICE_API_KEY environment variable or in app_config.json)
  • Required packages: openai, httpx, flask (for web UI)

Starting the Web UI

cd gondola_v2.0/venice-web-ui
python server.py

Then open http://localhost:5000 in your browser.

Starting the CLI

cd gondola_v2.0
python -m venice.cli

CLI Options

python -m venice.cli --workspace /path/to/project --model claude-opus-45
  • -w, --workspace - Set the working directory (default: gondola_v2.0)
  • -m, --model - Choose the AI model (default: claude-opus-45)

Web Interface

Layout Overview

  • Left Sidebar - Workspace selector, context pulse, quick macros, and Git status
  • Center Panel - Main chat interface with model selector and balance display
  • Bottom Panel - Real-time terminal output showing tool execution
  • Right Sidebar - Image editor and backup management

Workspace Selector

Use the dropdown at the top-left to quickly switch between project directories. Gondola will reinitialize its workspace and memory for the selected directory.

Context Pulse

The context pulse indicator shows how much of the model's context window is being used. When it fills up, older messages are automatically pruned to maintain conversation flow.

Model Selector

The dropdown in the header lets you switch between available models. Each model displays its rank badge and pricing information.

Image Analysis

Click the paperclip icon to attach an image for vision analysis. The image will be sent to a vision-capable model for description or analysis.

Terminal Panel

The terminal panel shows real-time output from tool executions, including file operations, command outputs, and syntax validation results.

CLI Mode

Commands

  • /model or /models - Open interactive model selector
  • /image PATH - Analyze an image file
  • /help - Show available commands
  • clear - Clear conversation history
  • exit or quit - Save session and exit

Agent Loop

The CLI operates in an autonomous agent loop. When you give a task, Gondola will:

  1. Think about the approach
  2. Execute tools as needed
  3. Continue until the task is complete or max turns (10) is reached
The agent will pause after 10 consecutive tool calls to prevent runaway loops. You can then provide additional guidance or let it continue.

Memory System

Gondola maintains persistent memory across sessions, stored in .venice_memory.json in each workspace.

What Gets Remembered

  • Project Notes - Manually saved notes using the remember tool
  • Session Summaries - Automatic summaries of what was accomplished each session
  • Files Touched - List of files modified in previous sessions
  • User Preferences - Custom settings like code style preferences

Using Memory

// Save a note
"Remember that the API key is stored in config.py"

// Recall everything
"What do you remember about this project?"

// Clear notes (keeps preferences)
"Forget all notes"

// Clear everything
"Clear all memories including preferences"
Memory context is automatically included in the system prompt at the start of each session.

Backup System

Every time Gondola edits a file, it automatically creates a backup in the .venice_backups directory.

Backup Format

.venice_backups/
  app.py.20240115_143022.bak
  config.py.20240115_143156.bak
  utils.py.20240115_144033.bak

Recovery Options

  • list_backups - See all available backups
  • list_backups("app.py") - Filter backups for specific file
  • restore_backup("app.py.20240115_143022.bak") - Restore specific backup
  • undo_edit("app.py") - Quick restore of most recent backup
Backups are stored locally and can accumulate over time. Periodically clean up old backups to save disk space.

Best Practices

Effective Prompting

  • Be Specific - "Add a login endpoint to app.py that validates username/password against the users table"
  • Provide Context - "The project uses Flask and SQLAlchemy. Add..."
  • Break Down Large Tasks - Instead of "refactor everything", ask for specific changes step by step

Working with Edits

  • The edit_file tool requires exact text matches - include enough context lines
  • For large changes, replace_lines is often more reliable than edit_file
  • Always let Gondola read a file before editing it

Managing Context

  • Clear conversation periodically for long sessions to free up context
  • Use map_project at the start to give Gondola an overview
  • The memory system persists important info across cleared conversations

Safety Tips

  • Gondola operates in a sandbox but can still modify files - review changes
  • Use undo_edit immediately if something goes wrong
  • For critical files, manually backup before major refactoring
  • Test changes with run_command before considering the task complete
Start new projects with "Map this project and explain the architecture" to give Gondola context about the codebase structure.

Troubleshooting

API Key Not Found

Set the VENICE_API_KEY environment variable or create app_config.json with:

{"venice_api_key": "your-key-here"}

Edit Failed - Search Block Not Found

The text to replace doesn't match exactly. Common causes:

  • Whitespace differences (tabs vs spaces, trailing spaces)
  • File was modified since last read
  • Not enough context lines to make the match unique

Solution: Have Gondola read the file again and retry with more context.

Syntax Error on Save

Gondola validates Python and JSON before saving. If validation fails, the file is NOT modified. Fix the syntax error and try again.

Timeout Errors

Long operations may timeout. Solutions:

  • Switch to a faster model
  • Break the task into smaller pieces
  • Clear conversation to reduce context size

Model Stuck / Empty Response

Some models may stall on complex prompts. Try:

  • Simplifying the request
  • Switching to a different model
  • Clearing conversation and starting fresh
